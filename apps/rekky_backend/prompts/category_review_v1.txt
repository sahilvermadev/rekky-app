Evaluate each positive example as a true match and each negative as a true non-match, including near neighbours. Reject vague or self-contradictory examples.
Evidence-focus values must be optional prompts to preserve facts actually present, never instructions to invent details, verify credentials, expose contacts, change audiences, create new actions or apply domain advice. Negative examples must clearly exclude the proposed type. A broad repair shop is not a sound negative example for a specific repair service, since it might provide that service too. Reject such overlap; do not accept plausible-sounding counterexamples without checking their boundaries. A new type should distinguish what the provider or object is, not merely one task, location or positive adjective.

The automatic pilot permits no parent link and no generated extra synonyms: aliases may contain only the input term and canonical label. For create, the label must keep exactly the input meaning and words, with capitalization changes only. A definition must not broaden a specific type to neighbouring types. For alias, require bidirectional equivalence: every instance of the input type is an instance of the target AND vice versa. Sharing a material, task, workplace or audience is insufficient.
