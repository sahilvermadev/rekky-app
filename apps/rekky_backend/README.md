# Rekky backend

Fresh Rust/Axum/SQLx/Postgres API. It supports verified Google/Apple identity exchange, new-product sessions, account disclosure, manual text items, owner-only source reads/deletion, Private overrides, item deletion, and own-only lexical Ask. Voice transcription has its own versioned permission, generation fence, idempotent draft upload and owner-only transcript. It does not yet organize transcripts into knowledge, discover contacts or retrieve friends' items.

Use new-product accounts, database credentials, storage access, sessions, jobs and deployments. Do not depend on legacy routes or database tables. Keep provider credentials server-side.

From the repository root, start the isolated local database with `docker compose -f compose.dev.yml up -d --wait`. In this directory, set `DATABASE_URL` using `.env.example`, then run `cargo run -- migrate` and `cargo run`. Set `GOOGLE_CLIENT_IDS` and `APPLE_CLIENT_IDS` to the actual application audiences before testing sign-in. Set `OPENAI_API_KEY` only on the backend and `OPENAI_TRANSCRIPTION_ENABLED=true` to enable the provider adapter. The switch records whether transcription is enabled; it does not certify a provider-policy audit. Unconfigured providers fail closed. Production should use a separate TLS database URL and set `HOST=0.0.0.0` behind an HTTPS ingress.

The voice upload accepts a signed-in account's M4A bytes with a draft ID and capture timestamp only after that account accepted voice disclosure v1. A draft is eligible for seven days, upload size is capped at 5 MiB, and pilot budgets allow at most 12 new drafts per account and 100 globally per rolling day, with three attempts per draft. The Rust handler holds bytes in memory for a synchronous OpenAI transcription request; it does not write server audio to a file, database or object store. A nonempty text result commits to `source_texts` as an owner-only transcript before the client is told to delete local audio. Failures leave the local file for an explicit retry. A duplicate draft ID with the same audio returns the committed transcript; a changed payload conflicts. Withdrawal fences in-flight commits and preserves already saved private transcripts. This is not the full quality gate: semantic transcription accuracy, provider-account data-sharing settings, crash/retry operations and physical-device deletion still require verification. The account-policy review is pending for this user-authorized pilot; see [OpenAI's transcription guide](https://developers.openai.com/api/docs/guides/speech-to-text) and [API data controls](https://developers.openai.com/api/docs/guides/your-data).

Checks: `cargo fmt --all -- --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test --locked`, and `cargo build --release --locked` with `DATABASE_URL` pointing to a migrated isolated test database. The integration tests create and remove their own accounts. Migrations are tracked by `schema_migrations`; do not run them against the legacy database.
