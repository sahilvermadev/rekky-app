# Rekky backend

Fresh Rust/Axum/SQLx/Postgres API. It supports verified Google/Apple identity exchange, new-product sessions, account disclosure, manual text items, owner-only source reads/deletion, Private overrides, item deletion, and own-only lexical Ask. Voice transcription has its own versioned permission, generation fence, idempotent draft upload and owner-only transcript. The first extraction path uses a separate text-processing disclosure, grounded source passages and private knowledge items tied to that capture. It does not yet complete the broader organization/evaluation gate, discover contacts or retrieve friends' items.

Use new-product accounts, database credentials, storage access, sessions, jobs and deployments. Do not depend on legacy routes or database tables. Keep provider credentials server-side.

From the repository root, start the isolated local database with `docker compose -f compose.dev.yml up -d --wait`. In this directory, set `DATABASE_URL` using `.env.example`, then run `cargo run -- migrate` and `cargo run`. Set `GOOGLE_CLIENT_IDS` and `APPLE_CLIENT_IDS` to the actual application audiences before testing sign-in. Set `OPENAI_API_KEY` only on the backend, `OPENAI_TRANSCRIPTION_ENABLED=true` for audio transcription and `OPENAI_EXTRACTION_ENABLED=true` for transcript extraction. These switches record whether the local pilot features are enabled; they do not certify a provider-policy audit. Unconfigured providers fail closed. Production should use a separate TLS database URL and set `HOST=0.0.0.0` behind an HTTPS ingress.

The voice upload accepts a signed-in account's M4A bytes with a draft ID and capture timestamp only after that account accepted voice disclosure v1. A draft is eligible for seven days, upload size is capped at 5 MiB, and pilot budgets allow at most 12 new drafts per account and 100 globally per rolling day, with three attempts per draft. The Rust handler holds bytes in memory for a synchronous OpenAI transcription request; it does not write server audio to a file, database or object store. A nonempty text result commits to `source_texts` as an owner-only transcript before the client is told to delete local audio. Failures leave the local file for an explicit retry. A duplicate draft ID with the same audio returns the committed transcript; a changed payload conflicts. Withdrawal fences in-flight commits and preserves already saved private transcripts. This is not the full quality gate: semantic transcription accuracy, provider-account data-sharing settings, crash/retry operations and physical-device deletion still require verification. The account-policy review is pending for this user-authorized pilot; see [OpenAI's transcription guide](https://developers.openai.com/api/docs/guides/speech-to-text) and [API data controls](https://developers.openai.com/api/docs/guides/your-data).

`POST /v1/voice-captures/{id}/extract` requires the independent transcript-processing disclosure and an owner-visible transcript. It calls `gpt-4.1-mini` using the Responses API with `store:false` and a strict JSON schema. A validator accepts only contiguous source word sequences as evidence, constructs item bodies from original transcript spans, and marks coverage under 80% partial. Up to five private items link to the original capture; Ask can search them immediately. An idempotent completed job cannot recreate a deleted item. Pilot limits are 6,000 transcript characters, 12 new captures per account and 100 globally per rolling day, with three attempts per capture. Deleting one of several items keeps their shared source until the last item is removed. This path does not yet prove semantic extraction quality or support explicit transcript correction/reprocess.

Checks: `cargo fmt --all -- --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test --locked`, and `cargo build --release --locked` with `DATABASE_URL` pointing to a migrated isolated test database. The integration tests create and remove their own accounts. Migrations are tracked by `schema_migrations`; do not run them against the legacy database.
