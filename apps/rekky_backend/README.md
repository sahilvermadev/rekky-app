# Rekky backend

Fresh Rust/Axum/SQLx/Postgres API. It supports verified Google/Apple identity exchange, new-product sessions, account disclosure, manual text items, owner-only source reads/deletion, Private overrides, item deletion, and own-only lexical Ask. Voice transcription has its own versioned permission, generation fence, idempotent draft upload and owner-only transcript. The first extraction path uses a separate text-processing disclosure, grounded source passages and private knowledge items tied to that capture. It does not yet complete the broader organization/evaluation gate, discover contacts or retrieve friends' items.

Use new-product accounts, database credentials, storage access, sessions, jobs and deployments. Do not depend on legacy routes or database tables. Keep provider credentials server-side.

From the repository root, start the isolated local database with `docker compose -f compose.dev.yml up -d --wait`. In this directory, set `DATABASE_URL` using `.env.example`, then run `cargo run -- migrate` and `cargo run`. Set `GOOGLE_CLIENT_IDS` and `APPLE_CLIENT_IDS` to the actual application audiences before testing sign-in. Set `OPENAI_API_KEY` only on the backend, `OPENAI_TRANSCRIPTION_ENABLED=true` for audio transcription and `OPENAI_EXTRACTION_ENABLED=true` for transcript extraction. These switches record whether the local pilot features are enabled; they do not certify a provider-policy audit. Unconfigured providers fail closed. Production should use a separate TLS database URL and set `HOST=0.0.0.0` behind an HTTPS ingress.

The primary `POST /v1/remember/{draft_id}` endpoint accepts account-owned M4A bytes and a capture timestamp after voice and extraction setup. It returns a durable receipt immediately. A Rust worker resumes leased jobs after restart, transcribes and extracts without needing a live mobile session. Audio is held temporarily in `voice_uploads` in the isolated pilot Postgres database, capped at 5 MiB per upload, 12 new uploads per account/day and 100 globally/day, with three attempts and a seven-day eligibility window. Accepted transcript commit clears the active database audio atomically; the phone deletes its copy after observing that receipt. Cancellation creates a tombstone even if it arrives before the upload. Permission generations fence cancelled work and late results. GET returns owner-only progress; DELETE cancels pending processing without deleting completed memories/sources. The older synchronous `/v1/voice-drafts/{id}/transcribe` route remains only for explicit legacy-draft recovery. See [one-tap storage and operational limits](../../docs/ONE_TAP_REMEMBER.md), including backup/WAL retention that must be resolved before production.

`POST /v1/voice-captures/{id}/extract` requires the independent transcript-processing disclosure and an owner-visible transcript. It calls `gpt-4.1-mini` using the Responses API with `store:false` and a strict JSON schema. A validator accepts only contiguous source word sequences as evidence, constructs item bodies from original transcript spans, and marks coverage under 80% partial. If strict evidence validation fails but the proposed subject occurs in the source, one private partial item preserves the full original transcript for review, without model-written claims. Up to five private items link to the original capture; Ask can search them immediately. An idempotent completed job cannot recreate a deleted item. Pilot limits are 6,000 transcript characters, 12 new captures per account and 100 globally per rolling day, with three attempts per capture. Deleting one of several items keeps their shared source until the last item is removed. This path does not yet prove semantic extraction quality or support explicit transcript correction/reprocess.

Checks: `cargo fmt --all -- --check`, `cargo clippy --all-targets -- -D warnings`, `cargo test --locked`, and `cargo build --release --locked` with `DATABASE_URL` pointing to a migrated isolated test database. The integration tests create and remove their own accounts. Migrations are tracked by `schema_migrations`; do not run them against the legacy database.
