# Provider phone completion

A provider's phone belongs to the recommendation. Friends-visible items carry it automatically; Private items keep it owner-only. There is no second audience field, contact sharing toggle or per-match sharing approval. The current pilot still has owner-only retrieval; actual friend viewing is an F-03 dependency.

## Mobile flow

- Account menu → Contact matching → Enable matching explains the behavior once, then requests native Contacts access. Android uses READ_CONTACTS only; iOS supports its native limited/full permission. Denial never prevents recording or manual phone entry.
- After foreground Library loading (including completed recordings), eligible people/service recommendations can acquire one clear saved number. Existing recommendations are eligible too. The app does not run this device operation while closed or guarantee background execution.
- Matching runs in memory on the phone and ranks the subject's distinctive name tokens, small spelling/vowel variations, a service alias vocabulary, category and locality clues. A unique full/display name can qualify without structured first/last fields; a name plus service can qualify despite extra locality words. A single fuzzy name needs service and locality corroboration. For example, a transcription variant of a taxi provider's name plus Landour can resolve to a contact saved as that name + Landor + Taxi. Require score ≥0.85 and a lead of ≥0.08 over the next candidate. These scores are evidence weights, not calibrated probabilities. Generic service-only matches, conflicting roles, weak/partial identity, close competitors, multiple numbers and missing country codes abstain. Unknown service words can still match through a distinctive full name. This is a local heuristic matcher, not a generative AI provider call or proof of current ownership. Multilingual aliases/transliterations beyond the implemented comparisons remain limited.
- Add contact → Find a saved contact enables matching if needed and completes a clear match; otherwise it presents local candidates. Choose from contacts opens the native picker. Manual entry is always available. Select the provider, never a referrer.
- Detail shows the saved contact name, Call, a selectable number and Change contact beside the destination actions. Call opens the OS dialer on user gesture. Full Edit supports adding/changing/clearing the number. Contact removal suppresses future automatic matching for that item.
- Disabling matching requires a server acknowledgement and cancels pending automatic writes by generation. It does not erase saved snapshots. Phone-book changes do not silently replace published numbers. A rename/kind change clears an inherited number; an explicit replacement in that edit is retained.

Only the selected number and its saved contact name go to the backend. Candidate lists, native IDs and unrelated address-book details never leave the phone; no contact data is sent to AI providers, public lookup or analytics. The attached label follows the same recommendation audience as its number. Phone numbers are not added to recommendation prose or search projections. Matching uses the subject, category and locality fields, never referrer names in source/attribution. Native access does not enable account-level automatic matching by itself.

## API and persistence

`GET /v1/me/contact-matching` returns `{ "enabled": false, "generation": 0 }` before setup. `POST` accepts `{ "enabled": true|false }` and increments the generation on every change. Migration 012 stores this account-specific preference. Automatic attachment locks that preference while committing; an acknowledged disable cannot be followed by a write using the old generation.

`PATCH /v1/items/{id}/contact` requires a signed-in disclosed owner and `If-Match: <revision>`:

- `{ "mode": "automatic", "phone": "+919876543210", "generation": 1 }`: enabled current generation, person/service item, no existing contact or removal override.
- `{ "mode": "set", "phone": "+919876543210" }`: explicit manual/picker attachment or replacement; does not require global matching permission.
- `{ "mode": "none" }`: removes the snapshot and persists `contact_matching: "off"` to prevent resurrection.

`saved_name` is optional for old clients and manual entry, trimmed, bounded to 200 characters and rejects control characters. New automatic/picker attachments include it. An explicitly cleared name is stored as an empty string, so automatic label backfill cannot undo that choice. Full Edit can change it; changing a number clears an inherited label unless a replacement is entered.

Saved v2 JSON adds `contact: { "phone": "+919876543210", "origin": "contacts"|"user", "saved_name": "Maya Rao" }`. No phone-specific visibility exists. Each successful mutation increments the item revision and preserves content/audience/source. Normalize harmless phone separators but require `+` and 8–15 digits, no leading zero, extensions or dial-control characters. Country is never inferred from a device locale.

Full content edits accept optional `contact: {mode: keep|set|none, phone?: string, saved_name?: string}`; omission means keep for old clients. Unrelated edits preserve the snapshot/removal override; subject/kind changes clear inherited contact. Current AI refinement skips contact-bearing/explicitly suppressed legacy recommendations and revisions fence in-flight refinement. Future refinement versions must deliberately preserve this precedence. Source deletion leaves the independently attached snapshot; item deletion removes authorized access. Future Friends APIs must apply item authorization before returning the complete snapshot, including previews/actions/caches.

Automatic matching continues while a recommendation is being read; the row updates live. An active editor/contact chooser pauses new batches to reduce revision conflicts. New Library snapshots received during a batch are processed afterwards. Existing numbers without labels can receive `PATCH .../contact` with `{ "mode": "describe", "phone": "+12025550123", "saved_name": "Maya Rao", "generation": 1 }`. This requires enabled matching, current generation/revision, the same existing number and no existing saved label. It preserves manual origin and matching suppression; it can never swap the phone or replace a label. Only an unambiguous contact found by that exact phone is eligible.
