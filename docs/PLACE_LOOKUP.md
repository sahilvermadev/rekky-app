# Public venue addresses in the reading sheet

Opening an owner’s recommendation now starts independent source and optional address loads. Summary and all saved details render immediately. The quote has no heading, privacy subtitle or standalone deletion control. Whole-recommendation deletion and its existing shared-source lifecycle remain intact. The backend source-deletion route remains for compatibility/maintenance, but the mobile client no longer exposes or calls it. Sources remain owner-only despite removing that visible subtitle.

`POST /v1/items/{id}/place` uses the signed-in/disclosed owner’s current saved item, not arbitrary client-supplied query text. This pilot covers explicit restaurant, café, bar and hotel categories with exactly one stated venue locality and an automatic destination. Private people, unspecified places, historical/service-area locations, conflicting branches, custom destinations and deliberate no-link settings do not trigger lookup. Only the public venue name and locality go to Google; no source, recommendation prose, attribution, contact, account identity or device position is sent.

The backend makes one Google Places Text Search (New) request with a narrow field mask and a six-second timeout. It accepts a single operational establishment with the same distinctive name tokens and all supplied locality tokens, recognizing Bangalore/Bengaluru and Bombay/Mumbai. Additional branches, paginated results, malformed data or third-party attribution requirements not supported by this pilot return no match. This conservative rule can miss genuine matches and cannot establish general identity precision; no matching quality gate is declared passed. Supported matches display Google’s address with Google Maps attribution and a place-ID destination. Fallbacks keep the recorded locality and ordinary Maps search. Original locations and owner edits are never overwritten.

Google content is transient: the response uses `Cache-Control: private, no-store`, the app holds it only in the mounted detail sheet, and neither address nor listing data is saved to the item, local storage or search index. The one-day rolling budget reserves calls transactionally before provider dispatch: 20 per owner, 100 globally, and duplicate requests for an item suppressed for ten seconds. No paid automatic retry. Reservations contain only owner/item IDs and timestamps; account/item hard deletion anonymizes their references so global accounting survives. Expired reservations are pruned during subsequent lookups. The server rechecks session validity and the item revision/liveness after Google responds.

[Shared response fixture](../contracts/rekky/v1/fixtures/resolved_place.json) uses invented content. `GOOGLE_PLACES_ENABLED=false` is the default; the Maps key stays exclusively in the ignored backend environment. The current user's existing credential was reused for this requested local pilot, without copying other legacy configuration or data. Public rollout still needs the provider disclosures and public policies already listed as open in the canonical plan.

Implementation references: [Text Search request/field masks](https://developers.google.com/maps/documentation/places/web-service/text-search), [Maps URLs and place IDs](https://developers.google.com/maps/documentation/urls/get-started), and [Google content attribution/storage policies](https://developers.google.com/maps/documentation/places/web-service/policies). The Maps button itself supplies the required Google Maps text attribution next to the returned address, including while the destination opens.
