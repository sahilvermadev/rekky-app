# Early retrieval evaluation

`ask_text_seed_v0.json` is a synthetic, labelled text-only seed. It exercises paraphrased recall, warnings, a same-name pair, an unknown service area, city mismatch, Hindi/Hinglish and no-answer behavior. It contains no user data or audio. `apps/rekky_backend/test/ask_evaluation.test.ts` loads the seed, saves its items through the real API in an isolated account and measures own-Ask results against its labels.

Baseline on 2026-09-25 after filtering generic question words: expected item appeared in the top five for **8/9 answerable questions** (Wilson 95% interval about 0.565–0.980). By language: English 7/7 (0.646–1.000), Hindi 0/1 (0.000–0.793), Hinglish 1/1 (0.207–1.000). A forbidden item appeared in **3/10 queries** (0.108–0.603), including both city-scoped ramen questions and the same-name tutor question. Before generic-word filtering, the no-answer dentist query also returned an unrelated item. The tests report these counts but do not treat the tiny synthetic set as a launch gate.

These are candidate-retrieval results only. Ask currently returns source-labelled item snippets with `answer: null`; it has no city-role enforcement, semantic Hindi match, capability validation or answer synthesis. A top-five hit does not mean the item is actionable or that a caveat was interpreted correctly. The false positives are concrete F-01 retrieval work, especially hard location rules and no-answer suppression. The next set needs human-labelled audio → transcript → claim → later-question links, separate development/held-out splits and actual phone tests before any quality claim.
