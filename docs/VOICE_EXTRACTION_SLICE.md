# Transcript to private knowledge (F-01.2 pilot)

This slice lets a signed-in owner turn a retained private voice transcript into up to five private recommendations. For an existing transcript, **Save recommendation** is available in the draft/transcript sheet. After one separate disclosure for sending transcript text to OpenAI, later transcriptions attempt extraction automatically after their audio is acknowledged for deletion. The saved items appear in Library and own Ask; this pilot does not publish them to friends.

The backend uses `gpt-4.1-mini` through the [Responses API structured-output format](https://developers.openai.com/api/docs/guides/structured-outputs) with `store:false`. The model proposes subjects and evidence passages. Rust matches each passage to the transcript as a contiguous sequence of the same words, allowing punctuation and whitespace differences, then builds each item's body from the original source span. Unsupported or changed words fail strict validation. If the proposed subject itself is present in the source, a conservative fallback saves one **private, partial, review-needed** item containing the entire original transcript; it never saves the model's ungrounded wording. If no proposed subject is grounded, no item is saved. The validator also marks a capture partial when accepted evidence covers less than 80% of the transcript's alphanumeric characters. Neither that mechanical coverage check nor the fallback proves faithful organization; the F-00.5 labelled evaluation remains required. Source transcripts are owner-only and are never item search text for friends.

`GET/POST /v1/me/transcript-extraction-permission` maintains a versioned, independent text-processing choice. Withdrawal fences late extraction results and retains existing items and transcripts. `POST /v1/voice-captures/{id}/extract` is owner-scoped, bounded to 6,000 transcript characters, three attempts per capture and 12 new jobs per account/100 globally in a rolling day. A completed retry returns only still-live items; it cannot recreate a deleted item. Source revision and permission generation are checked again before committing. Deleting one item from a multi-item voice capture keeps the shared transcript until the last item is deleted.

Rust/Postgres tests cover separate consent, exact evidence, punctuation recovery, rejection of fabricated words, private source-preserving fallback, owner-only Ask, idempotency, and shared-source deletion. Flutter tests cover the API request without a second audio upload. One synthetic live call verified the provider response shape. The first real attempt against the user's private transcript was rejected by strict evidence validation. The user explicitly approved two further attempts: the second also failed, and the third saved one private partial item through the source-preserving fallback. Database checks confirmed the item's body is exactly the 265-character original transcript, its visibility is private, and its capture is partial. This is a retained, searchable review draft, **not** evidence that the model distilled the recommendation correctly. In particular, semantic extraction quality, multiple-item segmentation, source correction/reprocessing, iOS runtime, and the full low-touch recording-to-Ask journey remain unverified. The configured local OpenAI project data-sharing setting has not been reviewed, per the user's pilot decision.
