# Transcript to private knowledge (F-01.2 pilot)

This slice lets a signed-in owner turn a retained private voice transcript into up to five private recommendations. For an existing transcript, **Save recommendation** is available in the draft/transcript sheet. After one separate disclosure for sending transcript text to OpenAI, later transcriptions attempt extraction automatically after their audio is acknowledged for deletion. The saved items appear in Library and own Ask; this pilot does not publish them to friends.

The backend uses `gpt-4.1-mini` through the [Responses API structured-output format](https://developers.openai.com/api/docs/guides/structured-outputs) with `store:false`. The model proposes subjects and evidence passages. Rust matches each passage to the transcript as a contiguous sequence of the same words, allowing punctuation and whitespace differences, then builds each item's body from the original source span. Unsupported or changed words fail validation and leave the transcript private for retry. It marks a capture partial when accepted evidence covers less than 80% of the transcript's alphanumeric characters. That mechanical coverage check cannot prove that every important nuance or warning survived; the F-00.5 labelled evaluation remains required. Source transcripts are owner-only and are never item search text for friends.

`GET/POST /v1/me/transcript-extraction-permission` maintains a versioned, independent text-processing choice. Withdrawal fences late extraction results and retains existing items and transcripts. `POST /v1/voice-captures/{id}/extract` is owner-scoped, bounded to 6,000 transcript characters, three attempts per capture and 12 new jobs per account/100 globally in a rolling day. A completed retry returns only still-live items; it cannot recreate a deleted item. Source revision and permission generation are checked again before committing. Deleting one item from a multi-item voice capture keeps the shared transcript until the last item is deleted.

Rust/Postgres tests cover separate consent, exact evidence, punctuation recovery, rejection of fabricated words, owner-only Ask, idempotency, and shared-source deletion. Flutter tests cover the API request without a second audio upload. One synthetic live call verified the provider response shape. The first real attempt against the user's private transcript was rejected by strict evidence validation; no knowledge item was saved and the transcript remains available. The matcher has since been tightened to accept word-identical punctuation variations, but that private transcript has **not** been retried. In particular, semantic extraction quality, multiple-item segmentation, source correction/reprocessing, iOS runtime, and the full low-touch recording-to-Ask journey remain unverified. The configured local OpenAI project data-sharing setting has not been reviewed, per the user's pilot decision.
