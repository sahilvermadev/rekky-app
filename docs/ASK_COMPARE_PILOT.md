# ASK-3 — bounded comparisons of saved knowledge

Implemented 2026-09-28 as a pilot checkpoint within the [Ask plan](ASK_EXPERIENCE_PLAN.md), not a completed release gate.

Ask can compare two to four own-library recommendations. The user can name options in a typed or spoken question, or select them from a previous answer with **Compare** chips and then tap **Compare N**. The selection is a turn-scoped referent, not a saved preference. A follow-up can select a participant in the comparison, change the criterion or ask about an unknown. When “these two” is ambiguous, the agent asks which options instead of guessing.

The Rust `present_answer` tool now accepts `intent=comparison` and a structured comparison of participant IDs, one to four shared dimensions, one cell per participant per dimension, an optional conclusion and per-participant citations. It can search/inspect normally or reuse fresh prior items; no category-specific comparison recipe is built in. Existing three-decision, four-read-tool, 50-second and $0.02 reserved-cost ceilings remain; the plan's larger provisional comparison budget was unnecessary in these development cases and is not enabled. The native Flutter view stacks dimensions vertically, shows unknowns explicitly, opens quoted saved evidence and offers only app-generated current Call/Maps actions. It uses the existing Ask visual language at narrow widths and large text.

The server validates referenced IDs, ownership, evidence IDs, cell counts, dimensions, result length and selected/excluded scope. A cell with no evidence becomes **Not saved** regardless of model prose. Conclusions require citations from every participant; unsupported conclusions are rejected. This is reference validation, not proof that cited prose is semantically correct. The model prompt preserves negation, past timing, unknown capacity/price, and treats personal estimated ratings as insufficient to decide suitability. Unsupported comparisons do not acquire fabricated data. Every participant is re-fetched and revision-checked when displaying an answer; editing or deleting any source clears the whole comparison and conclusion. Subsequent turns re-fetch current evidence and deleted selections fail before a model call. No raw transcript or phone-contact payload enters the Ask projection.

The [shared comparison fixture](../contracts/rekky/v1/fixtures/ask_comparison.json) contains invented recommendations. Rust tests cover forged IDs/evidence, missing cells, unknown-value normalization, replay, participant follow-ups, edits and deletion. Flutter tests cover selection, evidence, follow-up and 320/375/414/768 width at 200% text. The five-case [synthetic live-model report](evaluation/ask_comparison_probe_2026-09-28.json) checks an eight-person dinner against a higher-rated two-person venue; a four-seat taxi and past fare; Hinglish leather-versus-silk repair; four-way comparison; and an ambiguous “these two.” All passed after correcting test assertions for equivalent “not recorded” wording. They use invented notes in the isolated test database, not the user's Library. These development cases are not a held-out quality estimate.

Still open: the 120-query multilingual held-out gate and same-set fixed-pass baseline comparison, larger-library continuation, varied real spoken comparisons on devices, iOS runtime, accessibility screen-reader verification, and robust semantic support checking beyond referenced evidence IDs. ASK-4/5 durable history/preferences and friend/public exploration remain later slices.
